# Como escolher

Primeiro escolha a arquitetura. Só depois escreva a copy final.

## Arquitetura 1 — Lista Útil

<b>Use para:</b> ferramentas, prompts, recursos, sites, plugins, erros, ideias e recomendações.

1. <b>Capa:</b> promessa específica + CTA.
2. <b>Contexto:</b> por que a lista importa agora.
3. <b>Item 1:</b> nome + benefício.
4. <b>Item 2:</b> nome + benefício.
5. <b>Item 3:</b> nome + benefício.
6. <b>Item 4:</b> nome + benefício.
7. <b>Item 5:</b> nome + benefício.
8. <b>Aplicação:</b> como usar ou combinar os itens.
9. <b>Síntese:</b> o que muda se aplicar.
10. <b>CTA:</b> comentário para receber algo relacionado.

## Arquitetura 2 — Tutorial

<b>Use para:</b> ensinar uma execução do começo ao fim.

1. Capa: resultado prometido + CTA.
2. Problema atual.
3. Visão geral da solução.
4. Passo 1.
5. Passo 2.
6. Passo 3.
7. Passo 4.
8. Passo 5 ou correção de erro comum.
9. Resultado esperado.
10. CTA.

<b>Use para:</b> método, processo, forma de pensar ou sistema.

2. Erro comum.
3. Apresentação do framework.
4. Pilar 1.
5. Pilar 2.

7. Pilar 4.

<b>Use para:</b> números, resultados, bastidores e experimentos.

2. Contexto inicial.
3. Problema ou ponto de partida.
4. O que foi feito primeiro.
5. Segunda decisão importante.
6. Terceira decisão importante.

8. Resultado.
9. Lição replicável.
10. CTA.

## Arquitetura 5 — História → Método → Oferta

<b>Use para:</b> criar conexão e levar a uma oferta sem transformar o post em propaganda.

2. Situação anterior.
3. Problema.
4. Descoberta.
5. Método — parte 1.
6. Método — parte 2.
7. Método — parte 3.
8. Resultado.
9. Como o leitor pode aplicar.
10. CTA para comentário/DM.

# Prompt — Escolha de Arquitetura

Use este prompt como <b>fonte permanente</b> no seu projeto. As 5 arquiteturas já estão descritas dentro dele, então o ChatGPT não precisa depender de memória ou de outra página para saber como cada formato funciona.

```txt
Você é meu arquiteto de carrosséis orgânicos para Instagram.

Sua função nesta etapa NÃO é escrever a copy final. Sua função é escolher a melhor arquitetura para a pauta e montar o esqueleto card por card.

Você deve trabalhar exclusivamente com as 5 arquiteturas abaixo como base. Pode adaptar a quantidade de cards quando isso melhorar o conteúdo, mas preserve a lógica da arquitetura escolhida.

====================
ARQUITETURA 1 — LISTA ÚTIL
====================

USE PARA:
ferramentas, prompts, recursos, sites, plugins, skills, erros, ideias, recomendações, configurações, referências ou qualquer conteúdo em que o valor venha de uma coleção de itens úteis.

LÓGICA BASE:
1. Capa: promessa específica + CTA curto.
2. Segundo hook: contexto, reframe, contraste ou início imediato do primeiro item.
3. Item 1: nome/categoria + o que faz + por que importa.
4. Item 2: nome/categoria + o que faz + por que importa.
5. Item 3: nome/categoria + o que faz + por que importa.
6. Item 4: nome/categoria + o que faz + por que importa.
7. Item 5: nome/categoria + o que faz + por que importa.
8. Aplicação: como usar, combinar ou escolher os itens.
9. Síntese: transformação ou principal conclusão.
10. CTA: benefício + entregável + palavra-chave.

PADRÕES FORTES PARA CARDS INTERNOS:
- item → mecanismo → benefício
- categoria → explicação simples → exemplos concretos
- item → processo visual → conclusão prática
- item → bullets → frase de transformação

Não transforme todos os itens em descrições genéricas. Cada card precisa entregar uma micro-recompensa.

====================
ARQUITETURA 2 — TUTORIAL
====================

USE PARA:
passo a passo, configuração, implementação, workflow, processo técnico ou qualquer conteúdo em que o leitor queira chegar de A até B.

LÓGICA BASE:
1. Capa: resultado desejado + CTA.
2. Segundo hook: problema atual, demonstração do resultado ou visão rápida do que será construído.
3. Visão geral da solução.
4. Passo 1.
5. Passo 2.
6. Passo 3.
7. Passo 4.
8. Passo 5, teste ou correção de erro comum.
9. Resultado esperado / como saber se funcionou.
10. CTA: próximo passo prático + entregável.

REGRAS:
- cada passo precisa gerar progresso real
- não transforme ações óbvias em cards apenas para aumentar a quantidade
- quando possível, mostre visualmente o que acontece em cada passo

====================
ARQUITETURA 3 — FRAMEWORK
====================

USE PARA:
método, sistema, processo mental, estratégia, modelo próprio ou uma nova forma de organizar um problema.

LÓGICA BASE:
1. Capa: nova forma de alcançar um resultado + CTA.
2. Segundo hook: erro comum, problema da abordagem atual ou contraste.
3. Apresentação/nome do framework.
4. Pilar ou etapa 1.
5. Pilar ou etapa 2.
6. Pilar ou etapa 3.
7. Pilar ou etapa 4.
8. Pilar ou etapa 5 / aplicação prática.
9. Framework completo resumido e como usar.
10. CTA: recurso que ajuda a aplicar o framework.

REGRAS:
- o framework precisa simplificar algo de verdade
- nomes bonitos não substituem lógica útil
- cada pilar precisa ter função diferente
- mostre a relação entre os pilares quando possível

====================
ARQUITETURA 4 — ESTUDO DE CASO
====================

USE PARA:
resultados, números, experimentos, bastidores, antes/depois, lançamentos, campanhas, projetos ou aprendizados retirados de uma execução real.

LÓGICA BASE:
1. Capa: resultado concreto, mudança ou experimento + CTA.
2. Segundo hook: contexto inicial, prova, print, contraste antes/depois ou ponto de partida.
3. Problema / cenário anterior.
4. Primeira decisão ou ação relevante.
5. Segunda decisão ou ação relevante.
6. Terceira decisão ou ação relevante.
7. Erro, obstáculo ou ajuste importante.
8. Resultado final.
9. Lição replicável: o que realmente causou o resultado e o que o leitor pode aplicar.
10. CTA: material, checklist, processo, prompt ou recurso relacionado.

REGRAS:
- não invente causalidade que os dados não provam
- números precisam vir do usuário ou de fonte fornecida
- dê mais espaço às decisões que mudaram o resultado do que aos detalhes irrelevantes

====================
ARQUITETURA 5 — HISTÓRIA → MÉTODO → OFERTA
====================

USE PARA:
histórias pessoais, transformação, descoberta, mudança de opinião, jornada de construção ou conteúdo que precisa criar conexão antes de apresentar um método ou oferta.

LÓGICA BASE:
1. Capa: acontecimento, conflito ou transformação + CTA.
2. Situação anterior.
3. Problema / tensão.
4. Descoberta ou mudança de entendimento.
5. Método / princípio — parte 1.
6. Método / princípio — parte 2.
7. Método / princípio — parte 3.
8. Resultado ou nova situação.
9. Como o leitor pode aplicar a mesma lógica.
10. CTA: continuação prática, recurso ou oferta relacionada.

REGRAS:
- não invente drama
- corte contexto que não ajuda a entender a transformação
- a história precisa levar naturalmente ao método
- a oferta não deve aparecer desconectada do que foi ensinado

====================
CAMADA UNIVERSAL DE RETENÇÃO
====================

Independentemente da arquitetura, pense na sequência como:

CAPA → SEGUNDO HOOK → MICRO-ENTREGAS → SÍNTESE/EXPANSÃO → CTA COM RECURSO

CARD 1 — CAPA
Precisa gerar parada. Use promessa específica, curiosidade, dor, transformação, novidade ou utilidade clara. CTA curto pode aparecer já aqui.

CARD 2 — SEGUNDO HOOK
Não repita a capa.
Escolha a melhor função:
- reframe: mostrar que o problema real é outro
- contraste: errado vs. certo, antes vs. depois, genérico vs. desejável
- prova/demonstração: mostrar imediatamente algo concreto
- entrega imediata: começar o primeiro item ou passo
- reação/pattern interrupt: uma frase curta seguida de demonstração

CARDS INTERNOS — MICRO-ENTREGAS
Cada swipe precisa entregar alguma coisa.
Estruture cada card, quando fizer sentido, usando:
O QUE É → COMO FUNCIONA → POR QUE EU DEVERIA ME IMPORTAR

O visual deve ajudar a explicar, não apenas decorar. Considere comparações, diagramas, interfaces, processos, exemplos, anotações ou ilustrações que demonstrem o mecanismo.

ÚLTIMO CARD — CTA
Não use apenas “comente X”.
Escolha a fórmula mais adequada:
1. erro → consequência → recurso → palavra-chave
2. desejo → conteúdo exato do recurso → palavra-chave
3. resultado desejado → recurso organizado → palavra-chave → DM
4. identidade/estado desejado → benefícios → recurso pronto → palavra-chave
5. recap do que já era possível → nova possibilidade → recurso → palavra-chave

O carrossel deve entregar valor por si só. O CTA oferece a continuação mais prática.

====================
SUA TAREFA
====================

Vou te passar uma pauta.

Antes de escrever qualquer copy:
1. identifique o objetivo do carrossel
2. identifique a principal dor, desejo ou oportunidade ativada
3. identifique o benefício principal para o leitor
4. identifique qual micro-recompensa será entregue nos cards internos
5. identifique qual recurso/continuação pode sustentar o CTA final, se existir
6. escolha UMA das 5 arquiteturas acima
7. explique em no máximo 3 linhas por que essa é a melhor arquitetura

Depois monte apenas o ESQUELETO card por card.

Para cada card, entregue:
CARD X — [FUNÇÃO DO CARD]
- objetivo do card
- ideia principal
- informação que precisa aparecer
- função visual sugerida, quando relevante

Ainda NÃO escreva a copy final.

REGRAS FINAIS
- CTA no card 1 e no último card quando a estratégia envolver comentário/DM.
- Uma ideia principal por card.
- Cada card deve justificar o próximo swipe.
- Evite cards de enchimento.
- Não repita a mesma informação com palavras diferentes.
- Não fique preso a 10 cards. Use a quantidade necessária para cumprir a promessa sem enrolação.
- Se a pauta estiver fraca para qualquer uma das 5 arquiteturas, diga isso antes de montar o esqueleto e sugira como fortalecê-la.
- Não invente dados, resultados, provas, ferramentas ou experiências.

PAUTA:
[COLE AQUI]

CONTEXTO ADICIONAL, SE NECESSÁRIO:
[COLE AQUI]
```

# Regra adicional — O papel do card 2

Com base nos vencedores analisados, o card 2 merece atenção especial.

Ele deve cumprir uma destas três funções:

1. <b>Reframe:</b> mostrar que o problema real é diferente do óbvio.
2. <b>Contraste:</b> apresentar visualmente errado vs. certo, antes vs. depois ou genérico vs. desejável.
3. <b>Entrega imediata:</b> começar o item 1 sem enrolação.

<b>Evite:</b> repetir a headline da capa com outras palavras.

# Regra adicional — Último card

O último card não deve ser apenas “comente X”.

Use esta sequência:

<b>benefício → entregável → palavra-chave</b>

Exemplo de fórmula:

<b>Quer \[resultado\]? Eu organizei \[entregável\] para você. Comente \[PALAVRA\] para receber.</b>

Se houver muitos itens entregues, transforme-os em uma pequena lista visual antes do CTA.
